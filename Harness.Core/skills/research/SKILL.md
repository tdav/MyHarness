## Применение

Когда пользователь просит исследовать, обобщить или проанализировать тему:

0. **Откройте прогресс** — файл `research-<тема>.progress.md` в рабочей папке. Если он уже есть,
   прочитайте его и продолжайте с первого пункта `[ ]` — не начинайте исследование заново.
   Если его нет, создайте через `file_access` по шаблону из раздела «Файл прогресса».
1. **Определите рамки** — решите, что здесь означает «исследование»: какие файлы/папки входят в рамки и каков результат (сводка, отчёт, решение). Запишите подвопросы темы отдельными пунктами `[ ]` в файл прогресса.
2. **Соберите данные** — используйте `search_files` для поиска релевантного содержимого в рабочей папке, затем `file_access` для чтения найденного. Используйте `run_shell` (Get-ChildItem, Select-String) для более широких проверок файловой системы.
3. **Проверьте по внешним источникам** — всё, чего нет в рабочей папке (версии, даты, цены,
   стандарты, состояние рынка), ищите через `web_search` и читайте через `web_fetch`. Никогда не
   берите такие факты из собственной памяти — она устарела. Рядом с каждым внешним фактом ставьте
   URL источника и дату публикации. Если веб-инструменты недоступны, так и напишите в отчёте и
   укажите, что данные не проверены.
4. **Вычислите** — когда нужны подсчёты, статистика или перекрёстные ссылки, пишите Python и запускайте через `execute_code`, а не считайте вручную.
5. **Обобщите** — запишите результат в файл в рабочей папке (например, `research-<тема> report.md`) через `file_access`, а также покажите пользователю ключевые выводы прямо в ответе.
6. **Сохраните** — запишите долговременные выводы в файловую память, чтобы следующая сессия могла на них опереться.

**После каждого выполненного шага** сразу отмечайте его `[x]` в файле прогресса — файл должен
отражать реальное состояние, а не намерения.

## Файл прогресса

`research-<тема>.progress.md` в рабочей папке:

```markdown
# Прогресс: <тема>
Статус: IN_PROGRESS

## Шаги
- [ ] 1. Рамки и подвопросы
- [ ] 2. Сбор данных из рабочей папки
- [ ] 3. Проверка внешних фактов (или отметка «веб недоступен»)
- [ ] 4. Вычисления (или «не требуются»)
- [ ] 5. Отчёт записан: research-<тема> report.md
- [ ] 6. Выводы сохранены в файловую память

## Подвопросы
- [ ] <подвопрос 1>
- [ ] <подвопрос 2>

## Открытые хвосты
- <что осталось проверить, если пришлось прерваться>
```

## Проверка завершённости (обязательный финальный шаг)

Прежде чем дать пользователю финальный ответ, перечитайте файл прогресса и проверьте:

- все пункты «Шаги» и «Подвопросы» отмечены `[x]`;
- файл отчёта действительно существует (`file_access` list/read, а не по памяти);
- у каждого утверждения в отчёте есть источник (`file:line` или URL);
- раздел «Открытые хвосты» пуст.

**Если хоть одно условие не выполнено — исследование НЕ закончено.** Не отвечайте пользователю
итогом: вернитесь к первому незакрытому пункту и продолжите работу. Так повторяйте, пока чек-лист
не закроется. Если пункт объективно невыполним (нет данных, нет доступа), не оставляйте его `[ ]` —
отметьте `[x] (не выполнено: причина)` и вынесите причину в отчёт как ограничение.

**Когда всё закрыто:** проставьте в файле прогресса `Статус: DONE` и завершите ответ строкой

```
✅ Исследование завершено: <тема> → <путь к отчёту> (шагов: N/N)
```

Без этой строки ответ считается промежуточным, и вы обязаны продолжать работу.

