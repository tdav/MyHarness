## 1. Что такое OCPP

**OCPP** (Open Charge Point Protocol) — это открытый протокол связи между зарядными станциями
для электромобилей (Charging Station, CS) и системой управления зарядкой (CSMS — Charging Station
Management System). Протокол стандартизирует обмен данными: авторизация пользователей, начало/остановка
зарядки, передача показаний счётчика, обновление прошивки, диагностика, умная зарядка и управление
тарифами.

**Ключевые свойства:**
- **Открытый стандарт** — спецификации публикуются свободно
- **Независимость от производителя** — любой CS может работать с любым CSMS
- **Гибкость** — поддерживает различные сценарии: от домашней зарядки до публичных сетей
- **Развитие** — протокол эволюционирует вместе с индустрией электромобильности

**Владелец стандарта:** Open Charge Alliance (OCA) — некоммерческая организация, развивающая
протокол. До 2023 года называлась Open Charge Alliance (основана участниками индустрии).

## 3. OCPP 2.0.1 — последняя версия

**Дата выпуска:** Март 2022 (официально опубликовано Open Charge Alliance).

OCPP 2.0.1 — это исправленный и дополненный релиз OCPP 2.0. Он не добавляет фундаментально новой
архитектуры, но исправляет ошибки, уточняет описания и добавляет важные функции, которые были
пропущены или недостаточно проработаны в OCPP 2.0.

### Ключевые нововведения OCPP 2.0.1

1. **Device Model (Модель устройства)** — новая концепция конфигурации зарядной станции.
   Вместо набора фиксированных параметров (как в 1.6), конфигурация представляется как иерархическое
   дерево логических компонентов (Component → Variable → Attribute). Это позволяет:
   - Динамически описывать конфигурацию любой станции
   - Поддерживать новые типы разъёмов и функций без изменения протокола
   - Универсально управлять гетерогенными станциями

2. **Расширенная безопасность** — встроенный профиль безопасности (Security Profile) с:
   - Поддержкой TLS 1.2/1.3
   - Взаимной аутентификацией по сертификатам
   - Подписанной прошивкой (firmware signing)
   - Управлением сертификатами (CertificateSigned, GetInstalledCertificateIds, DeleteCertificate)
   - Журналированием событий безопасности

3. **Display Message** — возможность отображать текстовые сообщения на дисплее станции:
   - Уведомления для пользователя ("Зарядка завершена", "Авторизация успешна" и т.д.)
   - Настраиваемый язык, приоритет, длительность

4. **ISO 15118 Plug & Charge (PnC)** — интеграция с стандартом ISO 15118:
   - Автоматическая авторизация по сертификату без RFID-карты или приложения
   - Обмен контрактными сертификатами через CSMS
   - Поддержка тарификации в реальном времени

5. **Улучшенная обработка ошибок** — каждое сообщение об ошибке содержит детализированный
   `reasonCode` и `additionalInfo`, что упрощает диагностику.

6. **Variable Message Rate Limiting** — управление частотой сообщений от станции к CSMS,
   что помогает при ограниченной пропускной способности (например, при работе через 2G/3G).

7. **Events and Notifications** — расширенная система событий и уведомлений, заменяющая
   разрозненные сообщения из 1.6 на единый механизм `NotifyEvent`.

## 4. Архитектура протокола

### Компоненты системы

```
┌──────────────────────────────────────────────────────────────────┐
│                         Сеть электрозарядки                       │
│                                                                  │
│  ┌──────────────┐         WebSocket/WSS          ┌────────────┐ │
│  │  Charging     │ ◄─────────────────────────────► │    CSMS    │ │
│  │  Station (CS) │                                │            │ │
│  │               │   JSON-сообщения               │            │ │
│  │  - EVSE       │                                │  - База    │ │
│  │  - Коннектор  │                                │    данных  │ │
│  │  - Счётчик    │                                │  - API     │ │
│  │  - Дисплей    │                                │  - Тарифы  │ │
│  │  - RFID       │                                │  - Журнал  │ │
│  └──────────────┘                                └────────────┘ │
│         │                                                         │
│         │ IEC 61851 / ISO 15118                                   │
│         ▼                                                         │
│  ┌──────────────┐                                                │
│  │ Электромобиль│                                                │
│  │   (EV)       │                                                │
│  └──────────────┘                                                │
└──────────────────────────────────────────────────────────────────┘
```

### Транспортный уровень

OCPP 2.0.1 использует **WebSocket** (RFC 6455) в качестве основного транспорта:

- **Формат данных:** JSON (JavaScript Object Notation)
- **Шифрование:** WSS (WebSocket Secure, TLS 1.2+)
- **Соединение:** Постоянное (persistent), инициируется зарядной станцией
- **Направление:** Station → CSMS (станция подключается к CSMS, не наоборот)
- **SOAP:** Поддержка SOAP/XML формально сохранена, но **не рекомендуется** для новых внедрений

### Формат сообщения OCPP 2.0.1

Каждое сообщение — это JSON-массив с 3 или 4 элементами:

#### CALL (запрос от отправителя к получателю)
```json
[
  2,                              // MessageTypeId = 2 (CALL)
  "19223206",                     // UniqueId — уникальный идентификатор сообщения
  "BootNotification",             // Action — название операции
  {                               // Payload — данные
    "reason": "PowerUp",
    "chargingStation": {
      "serialNumber": "123456",
      "model": "ModelX",
      "vendorName": "ACME",
      "firmwareVersion": "1.0.0"
    }
  }
]
```

#### CALLRESULT (успешный ответ)
```json
[
  3,                              // MessageTypeId = 3 (CALLRESULT)
  "19223206",                     // UniqueId — соответствует CALL
  {                               // Payload — результат
    "currentTime": "2022-01-01T00:00:00Z",
    "interval": 300,
    "status": "Accepted"
  }
]
```

#### CALLERROR (ошибка)
```json
[
  4,                              // MessageTypeId = 4 (CALLERROR)
  "19223206",                     // UniqueId
  "SecurityError",                // ErrorCode
  "Invalid certificate",          // ErrorDescription
  {                               // ErrorDetails
    "additionalInfo": "Certificate expired"
  }
]
```

### Типы сообщений

| MessageTypeId | Тип | Назначение |
|---------------|-----|-----------|
| 2 | CALL | Запрос/инициация операции |
| 3 | CALLRESULT | Успешный ответ на CALL |
| 4 | CALLERROR | Ошибка в ответ на CALL |

## 5. Профили OCPP 2.0.1

Профили (Functional Profiles) — это логические группы операций, которые зарядная станция
может поддерживать. Производитель заявляет поддержку конкретных профилей в зависимости от
возможностей устройства.

### Полный список профилей OCPP 2.0.1

| Профиль | Описание | Ключевые операции |
|---------|----------|-------------------|
| **CS (Charging Station)** | Базовые операции зарядной станции | BootNotification, Authorize, StartTransaction (через TransactionEvent), StatusNotification (через TransactionEvent) |
| **Authorization** | Управление авторизацией | Authorize, GetAuthorizationInformation, SignedUpdateFirmware |
| **Local Auth List** | Локальный список идентификаторов | SendLocalAuthList, GetLocalAuthListVersion |
| **Smart Charging** | Умная зарядка и управление мощностью | SetChargingProfile, GetChargingProfiles, ClearChargingProfile, ReportChargingProfiles |
| **Meter Values** | Передача показаний счётчика | TransactionEvent (с meterValue) |
| **Diagnostics** | Диагностика и журнал событий | GetLog, NotifyEvent, CustomerInformation |
| **Firmware Management** | Управление прошивкой | SignedUpdateFirmware, GetFirmwareStatus |
| **Security** | Безопасность | CertificateSigned, GetInstalledCertificateIds, DeleteCertificate, SignCertificate |
| **Display Message** | Сообщения на дисплее | SetDisplayMessage, GetDisplayMessage, ClearDisplayMessage, NotifyDisplayMessage |
| **ISO 15118 (PnC)** | Plug & Charge | — (интегрировано в Security и TransactionEvent) |
| **Tariff and Cost** | Тарифы и стоимость | TransactionEvent (с cost-данными), CostUpdated |

## 6. Сообщения и операции

### Основные операции OCPP 2.0.1

#### Инициализация и регистрация
| Операция | Направление | Описание |
|----------|-------------|----------|
| `BootNotification` | CS → CSMS | Станция уведомляет о запуске, отправляет модель, версию, серийный номер |
| `GetBaseReport` | CSMS → CS | Запрос отчёта о конфигурации (Device Model) |
| `GetReport` | CSMS → CS | Запрос детального отчёта по компонентам |
| `NotifyReport` | CS → CSMS | Передача запрошенного отчёта |

#### Авторизация
| Операция | Направление | Описание |
|----------|-------------|----------|
| `Authorize` | CS → CSMS | Запрос авторизации идентификатора (RFID, PnC) |
| `GetAuthorizationInformation` | CSMS → CS | Запрос информации об авторизации |

#### Транзакции (через TransactionEvent)

| Event Type | Описание |

| `Started` | Транзакция начата (разъём подключён, авторизован) |

| `EnergyOfferStarted` | Начало фактической подачи энергии |
| `EnergyOfferEnded` | Окончание подачи энергии |

#### Управление конфигурацией
| Операция | Направление | Описание |
|----------|-------------|----------|
| `SetVariables` | CSMS → CS | Установка значений переменных конфигурации |

| `SetMonitoringBase` | CSMS → CS | Настройка базового мониторинга |
| `SetMonitoringLevel` | CSMS → CS | Уровень детализации мониторинга |
| `ReportMonitoringStatus` | CS → CSMS | Отчёт о статусе мониторинга |

#### Диагностика и события
| Операция | Направление | Описание |
|----------|-------------|----------|

| `GetLog` | CSMS → CS | Запрос лога диагностики |
| `NotifyLogStatus` | CS → CSMS | Статус передачи лога |
| `NotifyCustomerInformation` | CS → CSMS | Информация о клиенте |

#### Прошивка
| Операция | Направление | Описание |
|----------|-------------|----------|
| `SignedUpdateFirmware` | CSMS → CS | Обновление прошивки с подписью |
| `GetFirmwareStatus` | CSMS → CS | Запрос статуса обновления |
| `NotifyFirmwareStatus` | CS → CSMS | Уведомление о статусе прошивки |

#### Безопасность (Security)
| Операция | Направление | Описание |
|----------|-------------|----------|
| `CertificateSigned` | CSMS → CS | Передача подписанного сертификата |

| Операция | Направление | Описание |
|----------|-------------|----------|

| `ClearDisplayMessage` | CSMS → CS | Очистить сообщение |

#### Умная зарядка (Smart Charging)

|----------|-------------|----------|

## 7. Безопасность и аутентификация

### Security Profiles (Профили безопасности)

OCPP 2.0.1 определяет несколько профилей безопасности. CSMS и CS согласовывают
используемый профиль.

| Профиль | Аутентификация | Шифрование | Уровень |
|---------|---------------|------------|---------|
| **1** | Без аутентификации | Нет | ⚠️ Не рекомендуется |
| **2** | Basic Authentication (логин/пароль) | Нет | ⚠️ Ограниченный |
| **3** | Basic Authentication + TLS | TLS 1.2+ | ✅ Рекомендуется |
| **6** | Mutual TLS (двусторонние сертификаты) | TLS 1.2+ | ✅ Высокий |

### Рекомендуемая конфигурация

```
Charging Station                        CSMS
    │                                     │
    │ ──── TLS 1.2+ (WSS) ───────────────► │
    │      [Сертификат станции]            │
    │      [Сертификат CSMS]              │
    │                                     │
    │ Mutual Authentication               │
    │ (двусторонняя проверка сертификатов)│
```

### Управление сертификатами

OCPP 2.0.1 вводит полноценный жизненный цикл сертификатов:

1. **Генерация CSR (Certificate Signing Request)** — станция генерирует ключ
   и создаёт CSR через `SignCertificate`
2. **Подписание CSMS** — CSMS подписывает CSR и отправляет обратно через
   `CertificateSigned`
3. **Установка** — станция устанавливает подписанный сертификат
4. **Мониторинг** — проверка статуса через `GetCertificateStatus` (OCSP)
5. **Обновление** — перед истечением срока — повтор цикла
6. **Удаление** — `DeleteCertificate` при компрометации или истечении

### Типы сертификатов

| Тип | Назначение |
|-----|-----------|
| CSMS Root Certificate | Корневой сертификат CSMS |
| Charging Station Certificate | Сертификат станции (для mutual TLS) |
| V2G Root Certificate | Корневой сертификат для Plug & Charge |
| Manufacturer Certificate | Сертификат производителя станции |
| Firmware Signing Certificate | Сертификат для проверки подписи прошивки |

### Подписанная прошивка (Signed Firmware)

В OCPP 2.0.1 обновление прошивки происходит через `SignedUpdateFirmware`:
- Прошивка подписана цифровым ключом производителя
- Станция проверяет подпись перед установкой
- Это предотвращает установку вредоносного ПО

## 8. Smart Charging (умная зарядка)

### Charging Profiles

OCPP 2.0.1 поддерживает иерархию профилей зарядки для управления мощностью:

```
Уровень приоритета:
┌─────────────────────────────────────┐
│ 1. TxDefaultProfile (по умолчанию)  │ ← Низший приоритет
│    (для разъёма/группы)              │
├─────────────────────────────────────┤
│ 2. TxProfile (для транзакции)        │ ← Высший приоритет
│    (для конкретной сессии зарядки)   │
└─────────────────────────────────────┘
```

### PurposeType (Назначение профиля)

| Purpose | Описание |
|---------|----------|
| `ChargePointMaxProfile` | Ограничение общей мощности всей станции |
| `TxDefaultProfile` | Ограничение для конкретного разъёма (без активной транзакции) |
| `TxProfile` | Ограничение для конкретной активной транзакции |

### ChargingSchedule (Расписание зарядки)

Профиль содержит расписание:
- **StartSchedule** — начало действия
- **Duration** — длительность
- **ChargingRateUnit** — единица измерения (A — амперы, W — ватты)
- **ChargingSchedulePeriod** — периоды с лимитами мощности
- **MinChargingRate** — минимальная скорость зарядки

### Smart Charging в OCPP 2.0.1 vs 1.6

| Возможность | OCPP 1.6 | OCPP 2.0.1 |
|-------------|----------|------------|
| Лимиты по току | ✅ | ✅ |
| Лимиты по мощности | ✅ | ✅ |
| Расписания | ✅ | ✅ (улучшенные) |
| Фазное распределение | ❌ | ✅ |
| Переменные профиля | ❌ | ✅ (через Device Model) |
| Динамические лимиты | Ограничено | ✅ |

## 9. ISO 15118 и Plug & Charge

### Plug & Charge (PnC)

OCPP 2.0.1 тесно интегрирован с **ISO 15118** — стандартом связи между электромобилем
и зарядной станцией.

```
Электромобиль (EV)           Зарядная станция (CS)           CSMS
     │                             │                          │
     │ ──── Plug & Cable ────────► │                          │
     │                             │                          │
     │ ──── ISO 15118 (PnC) ─────► │                          │
     │      (Взаимная аутентификация│                          │
     │       по сертификатам)      │                          │
     │                             │ ── OCPP 2.0.1 ──────────►│
     │                             │    Authorize (PnC)        │
     │                             │                          │
     │                             │ ◄── Authorization ────────│
     │                             │     (Contract Cert.)     │
     │                             │                          │
     │ ◄── Тариф, стоимость ───────│                          │
     │                             │                          │
     │ ──── Зарядка начинается ────│                          │
     │                             │ ── TransactionEvent ────►│
```

### Ключевые аспекты PnC в OCPP 2.0.1

1. **Контрактные сертификаты** — каждый EV имеет контрактный сертификат,
   выданный оператором мобильности (MO). CSMS проверяет его через V2G Root.
2. **Автоматическая авторизация** — водителю не нужен RFID, карта или приложение;
   сертификат передаётся автоматически через кабель.
3. **Тарификация в реальном времени** — тарифы передаются EV до начала зарядки,
   водитель видит стоимость на приборной панели EV.
4. **Журнал сессии** — данные о сессии (метраж, стоимость, время) передаются
   EV в конце зарядки для автоматической оплаты.
5. **Операции OCPP для PnC** — `Authorize` с PnC, `CertificateSigned`,
   `GetInstalledCertificateIds` (V2G Root), `SignCertificate`.

### Преимущества Plug & Charge

- ✅ Нет необходимости в RFID-картах
- ✅ Нет необходимости в мобильных приложениях
- ✅ Автоматическая оплата
- ✅ Высокий уровень безопасности (взаимная аутентификация)
- ✅ Удобство для водителя ("включил и заряжаешь")

## 10. Сравнение OCPP 1.6 vs 2.0.1

### Сводная таблица

| Характеристика | OCPP 1.6 | OCPP 2.0.1 |
|----------------|----------|------------|
| **Год выпуска** | 2015 | 2022 |
| **Транспорт** | SOAP или WebSocket/JSON | WebSocket/JSON (WSS) |
| **Формат данных** | JSON или XML | JSON |
| **Архитектура** | Фиксированные параметры | Device Model (логические компоненты) |
| **Безопасность** | Базовая (Basic Auth опционально) | Встроенная (TLS, сертификаты, подпись прошивки) |
| **Plug & Charge (ISO 15118)** | Не интегрирован | Полная интеграция |
| **Дисплейные сообщения** | Ограниченные | Полноценные (DisplayMessage) |
| **Умная зарядка** | Базовая | Расширенная (фазное распределение, динамика) |
| **Обработка ошибок** | ErrorCode + Info | reasonCode + additionalInfo (детализированная) |
| **Транзакции** | StartTransaction / StopTransaction | TransactionEvent (объединённое) |
| **Статус** | StatusNotification | TransactionEvent (включает статус) |
| **Профилей** | ~8 | ~11 (с DisplayMessage, Security, PnC) |
| **Зрелость** | Очень зрелая, массовое внедрение | Развивающаяся, постепенно внедряется |
| **Документация** | Хорошая, обширная | Детальная, но быстро эволюционирует |
| **Обратная совместимость** | — | Не совместима напрямую с 1.6 (новая архитектура) |

### Ключевые архитектурные отличия

#### 1. Транзакции
**OCPP 1.6:** Три отдельных операции — `StartTransaction`, `StopTransaction`,
`StatusNotification`.

**OCPP 2.0.1:** Одна операция `TransactionEvent` с типом события (`Started`,
`Updated`, `Ended`). Упрощает логику и снижает количество сообщений.

#### 2. Конфигурация
**OCPP 1.6:** `GetConfiguration` / `ChangeConfiguration` с жёстко заданными
ключами.

**OCPP 2.0.1:** `GetVariables` / `SetVariables` через Device Model — иерархию
Component → Variable → Attribute. Гибкая и расширяемая.

#### 3. Статус разъёма
**OCPP 1.6:** Отдельная операция `StatusNotification`.

**OCPP 2.0.1:** Включена в `TransactionEvent` (тип `Updated` с
`connectorStatus`).

#### 4. Безопасность
**OCPP 1.6:** Безопасность — опциональная надстройка.

**OCPP 2.0.1:** Безопасность — встроенная часть протокола с отдельным
профилем и операциями управления сертификатами.
